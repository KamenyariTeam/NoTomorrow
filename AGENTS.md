# No Tomorrow agent guide

## Project summary

No Tomorrow is an early-stage, single-player-first top-down immersive-sim project for Unreal Engine 5.8. `NoTomorrowGame` is the runtime module and `NoTomorrowEditor` contains editor-only extensions. The project uses Enhanced Input, Common UI, Gameplay Tags, Game Features, Modular Gameplay, the local `GameplayCore` plugin (gameplay experiences and tagged events), and the local `ModularGameplayActors` plugin.

C++ owns the reusable runtime foundations, engine integrations, modular actor bases, input plumbing, asset/experience loading, and editor extensions. Blueprints and assets configure concrete game classes, characters, input/camera data, experiences, cursors, maps, and presentation. Treat planned game concepts in prose as plans unless code or assets confirm them.

## Sources of truth

Use this priority when facts disagree:

1. Code, `.uproject`, module rules, plugin descriptors, and config.
2. Project agent documentation in this file and `.agents/documents/`.
3. `README.md` and other human-facing documentation.
4. Assumptions.

Verify behavior in code. When stale documentation is within the task's scope, update it; otherwise call out the mismatch.

## Working rules

- Inspect nearby code before introducing a pattern. Make the smallest coherent, reviewable change that solves the task.
- Preserve unrelated edits. Avoid broad cleanup, mass renaming, whole-file reformatting, and speculative abstractions.
- Explain assumptions that cannot be verified. Ask before adding a significant dependency, plugin, module, or architectural layer.
- Do not edit generated Unreal files or local output: `Binaries/`, `DerivedDataCache/`, `Intermediate/`, `Saved/`, IDE metadata, solution/project files generated by Unreal, or plugin equivalents.
- Update documentation when a public workflow or architectural boundary changes.
- Review the final diff before finishing.
- Before significant C++ additions or refactors, read `.agents/documents/cpp-style.md`.
- Before adding a subsystem, module, plugin, replicated system, or cross-feature dependency, read `.agents/documents/architecture.md`.
- The two supporting documents are not required for trivial Markdown-only edits.

## Validation

Choose validation proportional to the change:

- Inspect the final diff and run `git diff --check`.
- Parse or otherwise validate modified JSON, INI, TOML, Markdown, and scripts where tooling exists.
- Compile the affected Unreal module or the `NoTomorrowEditor` target when the local Engine and Windows toolchain are available.
- Run relevant Unreal automation tests when they exist.
- Report exactly what was run, what passed or failed, and what was not validated.

Never hardcode a developer's Engine installation path. Use Rider's configured Unreal Engine, the `.uproject` association, or a documented variable such as `UE_ROOT`.
